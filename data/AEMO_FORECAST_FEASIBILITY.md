# AEMO forecast ingestion feasibility — January 2025 smoke test

This is an **offline source audit**, not a new forecasting model or a test-set result. The sample contains 576 five-minute decision origins on **20–21 January 2025 Sydney time**, within the existing January–June tuning period. The target remains the realised NSW1 wholesale price for the five-minute interval **starting exactly 60 minutes after each decision**. The December 2025–February 2026 held-out period was not accessed.

## Official sources and coverage

[AEMO's pre-dispatch page](https://www.aemo.com.au/energy-systems/electricity/national-electricity-market-nem/data-nem/market-management-system-mms-data/pre-dispatch) describes P5MIN as five-minute price/demand forecasts updated every five minutes for twelve dispatch periods, and 30-minute predispatch as half-hourly updates through the end of the next market day. The public recent-report windows are two and fourteen days respectively; daily P5MIN and weekly predispatch report ZIPs are archived. The [currently listed P5MIN daily archive](https://www.nemweb.com.au/REPORTS/ARCHIVE/P5_Reports/) begins in November 2025, as does the [weekly predispatch report archive](https://www.nemweb.com.au/REPORTS/ARCHIVE/Predispatch_Reports/). Their listings do not provide January 2025 issued reports.

The separate [MMSDM monthly archive](https://www.nemweb.com.au/Data_Archive/Wholesale_Electricity/MMSDM/) has public table ZIPs. An index-only audit found the three requested table files in **all 35 monthly indexes from January 2023 through November 2025**; see `derived/aemo_forecast_archive_index.json` for exact index URLs and filenames. This establishes file presence, **not** complete row coverage or historical publication timestamps in every month. Filenames changed from `PUBLIC_DVD_...` in 2023–24 to `PUBLIC_ARCHIVE#...` in 2025. [AEMO's data model](https://tech-specs.docs.public.aemo.com.au/Content/TSP_EMMSDM52May2023/Electricity_Data_Model_5_2.htm) and [v5.5 changes](https://tech-specs.docs.public.aemo.com.au/Content/TSP_EMMSDM55_Apr2025/EMMS_DMv5.5_Apr25_1.htm) show that field sets evolve; the January 2025 P5MIN CSV uses schema version 9. A full 35-month schema and completeness audit remains future work.

The three January ZIPs total about **52.1 MB compressed / 253.1 MB expanded**. Representative P5MIN ZIP sizes from archive headers are 41.7 MB (January 2023), 42.2 MB (January 2024) and 54.3 MB (November 2025); the 30-minute monthly table ZIPs are roughly 0.1 MB for price and 0.8–1.0 MB for regional summary. Full report archives are far larger: the [November 2025 weekly predispatch report ZIPs](https://www.nemweb.com.au/REPORTS/ARCHIVE/Predispatch_Reports/) are about 124–128 MB each. The whole January 2025 MMSDM package is about 19 GB; this smoke test downloaded only the three named table ZIPs.

The [January 2025 MMSDM index](https://www.nemweb.com.au/Data_Archive/Wholesale_Electricity/MMSDM/2025/MMSDM_2025_01/MMSDM_Historical_Data_SQLLoader/DATA/) also lists `P5MIN_INTERCONNECTORSOLN` (14.9 MB), `PREDISPATCHINTERCONNECTORRES` (0.33 MB), and `PREDISPATCHLOAD` (16.2 MB). They were **not downloaded or joined**. P5MIN interconnector flow may be a useful run-vintage feature if its key and publication timing pass the same audit. The monthly 30-minute interconnector table may have the same snapshot limitation. [AEMO's data model](https://tech-specs.docs.public.aemo.com.au/Content/TSP_EMMSDM52May2023/Electricity_Data_Model_5_2.htm) describes unit-level predispatch load as private to its participant until the next day, so it must not be assumed to have been public at decision time.

All three ZIPs are immutable under `raw/aemo_forecast_2025_01/`. `manifest.json` records each URL, byte count, SHA-256, retrieval time and HTTP response headers. Re-running the downloader verifies cached checksums and does not replace a file. A small normalized vintage-preserving extract is in `derived/aemo_p5min_nsw1_2025-01-20_21.csv.gz`; it retains UTC run and target-start timestamps, price, intervention and selected regional MW fields. The [monthly archive index](https://www.nemweb.com.au/Data_Archive/Wholesale_Electricity/MMSDM/2025/MMSDM_2025_01/MMSDM_Historical_Data_SQLLoader/DATA/) currently shows an April 2026 modification date for these files; that is archive servicing time, **not January 2025 publication time**. The internal CSV header says it was produced in February 2025. These are hindsight extracts and may differ from an as-issued live feed.

## Decision-time and interval alignment

AEMO market timestamps are **fixed UTC+10 AEST**. The January sample is Sydney daylight time (**UTC+11 AEDT**); joins use UTC, with Sydney time only for calendar labels. Both P5MIN `RUN_DATETIME` and `INTERVAL_DATETIME` in the sampled file refer to **interval ends**. For example, the run stamped `2025/01/01 00:05:00` covers interval ends 00:05 through 01:00 AEST, corresponding to interval starts 00:00 through 00:55 AEST. The parser subtracts five minutes from the target end and divides `RRP` **AUD/MWh by 1,000** to get AUD/kWh. The 30-minute `DATETIME` is treated as an interval end in research, but these snapshot rows are deliberately excluded from decision-time joins.

`RUN_DATETIME` is a run identifier, **not a proven publication timestamp**. The P5MIN CSV has `LASTCHANGED`, around 4.5 minutes before `RUN_DATETIME` for most sampled rows; it is a row-change field, not a verified public release or receipt time. [AEMO's Project EDGE specification](https://www.aemo.com.au/-/media/files/initiatives/der/2023/project-edge---data-specification-part-b.pdf?la=en) gives a general guide of publication about 40 seconds into a dispatch interval, but no exact per-run publication time for this historical snapshot. We therefore test **assumed availability at run time plus 0, 1, 5 or 10 minutes**. These are conservative sensitivity assumptions relative to a run timestamp that marks the end of its first interval; they are not measured latencies. A real decision system would need publication or local receipt timestamps and further margin.

The default selector filters to `INTERVENTION=0`, retains the `RUN_DATETIME` vintage, chooses only a run assumed available by the decision, and rejects duplicate keys. The sample has no intervention-flagged P5MIN rows and no duplicate `(run, target, intervention)` keys. Later runs are never used to fill an earlier decision. AEMO's monthly revised realised prices can differ from a forecast file's first-period `RRP`; that discrepancy is not a forecast error and remains a revision/semantics question.

As a reconciliation check, **588** sampled first-period P5MIN rows overlap the January realised table. Their mean absolute difference is **$0.00884/kWh**, with a maximum **$0.10118/kWh**. This does not establish whether the gap comes from dispatch timing, later price adjustments or the archive extraction; it is a reason to retain both source versions and avoid calling the first P5MIN row a verified realised settlement price.

**The exact one-hour target is unsupported by P5MIN at decision time.** A twelve-period run has target-start leads of −5 through +50 minutes relative to its `RUN_DATETIME`. A decision at `t` would need a later run to obtain the interval starting at `t+60`. On all **576** sampled decisions, coverage at `t+60` is **0/576** for every tested delay. The maximum available lead is 50 minutes at zero assumed delay, 45 minutes at one or five minutes, and 40 minutes at ten minutes. The complete coverage counts by five-minute lead are in `derived/aemo_forecast_2025_01_smoke.json`.

The 30-minute predispatch product extends much farther, but its interval is **30 minutes, not the five-minute target**, and the sampled monthly tables do not preserve an issuable run vintage. A coarse 30-minute price forecast could be examined later as a separate predictor if historical as-issued reports and publication times are obtainable. It must not be silently scored as the exact five-minute target.

## Forecast baseline result

There are **zero eligible AEMO forecasts for the existing target**, so AEMO one-hour MAE, RMSE, median absolute error, bias, negative-price detection, $1/kWh spike detection and lead-time distribution are **not defined**. A same-row comparison with persistence or saved V2-A/GRU predictions likewise has zero rows. Reporting a different lead or 30-minute target as if it were the one-hour five-minute forecast would be misleading. This two-day tuning-period smoke test is an ingestion diagnostic, not independent model evaluation.

## Proposed decision-time-safe feature dictionary

These are **design proposals**, not features added to the current 41-column dataset. Each row requires a proven publication/receipt timestamp or an explicitly conservative availability assumption. Missing forecasts stay missing with an indicator; later vintages never backfill.

| Candidate feature | Unit and source | Availability rule |
| --- | --- | --- |
| Latest AEMO price for exact target | AUD/kWh, P5MIN `RRP` or a future exact-resolution product | Include only if an eligible vintage actually covers `t+60`; currently missing for P5MIN. |
| P5MIN price trajectory | AUD/kWh at +5, +10, … within genuinely available lead | Same vintage selected at `t`; report horizon-specific coverage. |
| Forecast regional demand | MW, P5MIN `TOTALDEMAND`/`DEMANDFORECAST` or valid predispatch vintage | Target-aligned vintage available by `t`; never revised realised demand. |
| Generation availability / interconnector flow | MW, regional P5MIN availability or separately audited interconnector table | Only public run-vintage fields with verified timing and schema. |
| Price and demand revisions | AUD/kWh and MW | Difference between two **already published** vintages for the same future target. |
| Known forecast error | AUD/kWh | Earlier forecast minus realised outcome only after that outcome and its assumed reporting delay are complete. |
| Forecast age and lead | Minutes | `t − publication_or_receipt_time`, and target start minus `t`; preserve missingness. |
| Forecast missingness / intervention | Boolean or categorical | Mark absent, stale, intervention or unverified feeds; do not substitute hindsight snapshots. |

Next separately reviewed experiments, if a valid historical feed can be established: (1) score AEMO forecasts alone on exactly aligned horizons; (2) append only decision-time-safe AEMO fields and train direct ML; (3) train ML to correct an eligible AEMO forecast residual; (4) combine verified short P5MIN and longer 30-minute products in a clearly defined multi-horizon system. None was trained here.

## Reproduction

From the project root, `python -c "from solaralpha.aemo_forecast_archive import fetch_tables; fetch_tables()"` downloads or verifies only the three January 2025 ZIPs. `python -m solaralpha.aemo_forecast_coverage` checks 35 official directory listings without downloading table payloads. `python -m solaralpha.aemo_forecast_diagnostic` regenerates the sample report from the frozen raw ZIPs and existing January realised CSV. The code uses only the Python standard library; no new dependency or interpreter change was made.
