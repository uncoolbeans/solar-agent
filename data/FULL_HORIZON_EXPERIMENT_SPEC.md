# Fixed 144-point price forecasting benchmark

This design was recorded before fitting any new dense-horizon model. Targets are realised NSW1 prices in AUD/kWh for the five-minute intervals starting at decision time plus **0, 5, 10, ..., 715 minutes**. The +0 settlement price is an unknown label. The frozen 41 feature columns and their availability assumptions are unchanged, including the two historical seasonal columns aligned to +60 minutes. The ten former direct XGBoost models are reused only after their source features, parameters and training/tuning labels match the dense target artifact exactly.

All 144 target labels must remain in their origin's chronological partition and outside the January 13–19, 2025 development week. The frozen feature-origin universe and its existing one-hour boundary exclusions are retained. The full-horizon intersection has **208,669 training, 49,838 January–June tuning and 43,909 reused July–November evaluation** origins; the 72-row TCN input excludes a further 71 early training origins. Historical context from an earlier partition remains available to a later decision. No December 2025–February 2026 held-out data are read.

## Resource estimate before new training

The six dense target and prior-day-seasonal arrays use **670.1 MiB on disk** as float64 `.npy` files; memory mapping avoids loading all six into RAM. The ten prior direct XGBoost fits took 13.5–35.4 seconds each, averaging 22.1 seconds. Extrapolating to **134 additional horizons** gives about **2,961 seconds (49 minutes) sequential fit time**, before data loading, evaluation and contention. Their mean model file was 3.04 MB, suggesting approximately **389 MiB** of additional model storage; actual sizes can differ. Resumable nonoverlapping batches checkpoint each model and its SHA-256 metadata immediately. A few four-thread CPU fits may run concurrently if memory permits, with the estimate treated as a planning figure rather than a guarantee. The 144-output TCN is expected to take several minutes based on the ten-output TCN's 268-second fit; it uses the existing CPU-only PyTorch environment.

## Frozen model configurations

Each new direct model uses V2-A's `reg:absoluteerror`, 1,000-estimator budget, depth 5, learning rate 0.03, 0.8 row/column subsampling, minimum child weight 10, L1 0.1, L2 1.0, histogram trees, seed 42, four CPU threads and 50-round early stopping on its own January–June tuning MAE. Each horizon can use all eligible training/tuning origins for that horizon, while every reported approach uses the identical full-horizon common evaluation origins. No hyperparameter search is performed.

The full-output TCN keeps the prior seven causal residual convolution blocks, 24 channels, kernel size 2, dilations 1–64 and 128-row receptive field over a lazy **72 × 41** history. Replacing `Linear(24, 10)` with unrestricted `Linear(24, 144)` changes the trainable parameter count from **10,306 to 13,656**. Its loss is `mean_{origin,horizon}|prediction − target|`, giving each of the 144 offsets equal weight on common origins. It reuses seed 42, AdamW learning rate 0.001, weight decay 0.0001, batch 512, four CPU threads, gradient clipping at norm 1, up to eight epochs and patience two with minimum improvement 0.0001 AUD/kWh. Only the January–June common-origin mean MAE selects the checkpoint. The original ten-output TCN remains unchanged.

The tuning-selected full hybrid chooses persistence or direct XGBoost independently at each offset using only common January–June tuning MAE, then freezes its 144 choices before reused evaluation. The fixed alternative uses persistence at +0/+5 and direct elsewhere. Both are compared with direct, TCN, persistence, previous-day seasonal, training-only constant median and training-only hour-of-week median on identical eligible origins. Development trajectory diagnostics measure the complete 144-point output; they are not a trading-profit test.

The saved-model interface accepts 72 ordered UTC five-minute feature rows plus the claimed end timestamp of the latest completed market reading. It checks feature order, shape, finite values, output shape/units and freshness, then returns 144 ordered UTC target starts and wholesale price predictions. A stale response carries `input_valid=False` for callers to reject. The interface cannot independently prove upstream publication or revision timing; its freshness field depends on truthful source metadata. No controller consumes the interface in this milestone.
