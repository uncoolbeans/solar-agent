# Fixed ten-output sequence experiment

This is **multi-task learning**: predicting each horizon is a related task, with one shared encoder and ten horizon-specific output rows. The earlier **direct** design fits a separate full model for each horizon, so its representations and output weights are independent. The **horizon-conditioned** XGBoost design fits one scalar-output function `f(features, horizon_minutes)` and calls it ten times with different horizon inputs. The multi-output network evaluates its shared encoder once and emits all ten prices together. These designs also differ in input history, labeled training examples, and total capacity, so a score difference alone cannot identify the effect of sharing.

The machine-readable `models/price_multi_output_neural_v1/design.json` was saved before training. This experiment changes the original compact one-hour sequence networks only at their final linear head. The input remains a lazy window of 72 five-minute rows × 41 original decision-time-safe features, ending at decision interval start `t`. The head emits ten unrestricted prices for intervals **starting** at `t + {0, 5, 15, 30, 60, 120, 180, 360, 540, 715}` minutes. The current +0 settlement is unknown at the decision and is only a label. The original daily and weekly seasonal input columns remain aligned to the old +60-minute target time; they are historical observations, not new horizon-aligned features.

For a network, `z_t = g_θ(X_{t-71:t})` is its final recurrent hidden state or final causal-convolution feature vector. A ten-row linear head predicts `p̂_t = W z_t + b`, where row `j` of `W` and entry `j` of `b` belong to horizon `j`. The body parameters `θ` are shared across horizons; the output weights are separate. The loss is `(1/(10N)) Σ_t Σ_j |p̂_{t,j} − p_{t,j}|`. Tuning uses the arithmetic mean of ten horizon MAEs on common January–June 2025 origins; because every horizon has the same origin count, this equals the pooled output MAE. Sharing may improve sample efficiency when horizons respond to the same history. Negative transfer is possible when the shared representation cannot retain information needed by a particular horizon. This comparison does not isolate representation sharing from changes in training targets or head capacity.

| Architecture | Shared body | Ten-output head | Trainable parameters |
| --- | --- | --- | ---: |
| LSTM | One recurrent layer, hidden width 32; input/forget/output gates and cell state | Linear(32, 10) | 9,930 |
| GRU | One recurrent layer, hidden width 40; update/reset gates | Linear(40, 10) | 10,370 |
| TCN | Seven causal residual Conv1d blocks, 24 channels, kernel 2, dilations 1–64; receptive field 128 rows | Linear(24, 10) | 10,306 |

The prior one-output heads were Linear(32, 1), Linear(40, 1) and Linear(24, 1), with 9,633, 10,001 and 10,081 total parameters. Thus the new models have 297, 369 and 225 extra parameters respectively, while emitting ten values per decision. The TCN receptive field remains greater than the 72 available input rows. Unrestricted linear heads can predict negative prices.

The checksum-verified multi-horizon target artifact and original sequence context yield **208,598 training**, **49,838 tuning** and **43,909 reused development evaluation** common origins. Seventy-one early training origins lack a complete historical window. No tuning or evaluation origin is lost. Chronological partitions, development-week origin/target exclusions, and target boundary checks come from the frozen source artifacts. The scaler is fitted on the original 208,800 training feature rows only. Sliding windows are sliced from one shared matrix when requested; overlapping windows are not materialised as a full tensor.

The fixed CPU plan reuses seed 42, four PyTorch threads, batch size 512, zero loader workers, MAE loss, AdamW learning rate 0.001 and weight decay 0.0001, gradient clipping at norm 1, at most eight epochs, patience two, and a minimum tuning-MAE improvement of 0.0001 AUD/kWh to replace a checkpoint. January–June tuning chooses each model's epoch and the provisional neural candidate. July–November has already been examined and is **reused development evaluation**. The held-out December 2025–February 2026 period is not loaded. The installed PyTorch 2.15.0+cpu in the existing Python 3.14.7 environment is reused; no dependency or interpreter changes are required.

The short four-batch benchmark measured approximately 0.47 s LSTM, 0.72 s GRU and 0.46 s TCN. These are runtime checks, not architecture selection. Prior one-hour neural models, direct/shared XGBoost models, baselines, simulator and trading controllers remain untouched. Ten sparse forecasts do not establish a validated full 144-interval MPC price trajectory.
